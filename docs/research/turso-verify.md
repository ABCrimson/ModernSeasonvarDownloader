## Corrected facts
- Depend on: `turso = "0.7.2"` (stable) — 0.8.0-pre.x are pre-releases; workspace version on main is 0.8.0-pre.7.
- Windows multi-process IS reachable from the `turso` crate today (experimental): `Builder::new_local(path).experimental_multiprocess_wal(true).with_io("experimental_win_iocp".to_string()).build().await` (0.7.2) / `.with_io(IoBackend::IOCP)` (main). Both processes must use the same mode or the second gets LockingError ("already open with/without experimental multiprocess WAL in another process"). It is labelled not-production-ready; CLI+GUI sharing one file remains a risk but is not a hard blocker.
- Without IOCP on Windows the multiprocess flag silently no-ops and the file stays single-process-locked.
- `turso` crate builds with pure-rust crypto by default (no cl.exe requirement via this path).
- Open issue count: 716 issues (868 incl. PRs).
- Minor: bindings/rust README still shows `turso = "0.4.3"` example — stale.
