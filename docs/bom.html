Context

You chose a core-first Cargo workspace: a pure-Rust seasonvar-core library consumed by a seasonvar CLI and a Tauri 2 desktop app with a React UI. Scope is parity + finishing the two stubs (real download manager, history) + what the site now exposes (translations, seasons, metadata). Pre-release policy (your call, v2): adopt the next major/minor of a chosen package once it reaches RC (Vitest 5, pnpm 12, radix-ui 1.7), plus React's canary channel, plus Rust beta as the toolchain's RC; alpha/dev/nightly builds (TS 7.1-dev, Playwright 1.63-alpha, zod 4.5-canary, Tailwind insiders) stay out. Risks & kill criteria

Bleeding-edge bets (each has a named fallback)

  • Rust 1.99 beta regresses a crate build → 1.98.0 stable (one line in rust-toolchain.toml).
  • pnpm 12 RC lockfile/CI glitch → 11.22.0.
  • React 19.3 canary API churn → 19.2.8; we only touch <Activity>/<ViewTransition> in two places, behind tiny wrappers.
  • Vitest 5 RC + vitest-browser-react peer mismatch → whole Vitest set to 4.1.11 (Browser Mode unchanged).
  • radix-ui 1.7 RC breaks a shadcn component → 1.6.7.
  • TypeScript 7 native breaks a tool's types → 6.0.3. Kill criterion: more than one hour lost.
  • oxlint type-aware false positives → rule-level disable; the formatter/style side (Biome) is unaffected.
  • tauri-specta RC won't compile against tauri 2.11.5 → hand-written invoke wrappers + zod.
  • React Compiler mis-memoizes → "use no memo" on that file, or disable globally.
  • Vite 8 / rolldown plugin incompatibility → Vite 7.3.6 with identical config.
  • jiff API churn → chrono. macOS universal build fails on the runner → arm64 only.

Project-level risks

  • seasonvar rotates Playerjs keys → markers-as-data decoder + fixture refresh; expected, cheap.
  • Playlist endpoint moves behind auth/DRM → this would end the "direct mp4" approach; kill criterion for the core pipeline (fallback: none planned in v1).
  • ubuntu-22.04 runner retired → ubuntu-24.04 and document the glibc floor.
  • Repo recreation is irreversible → done only at implementation start, after you run gh auth refresh -s delete_repo; the fork holds nothing but upstream's commits.
  • Aggregate RC risk: seven pre-release pins at once. Mitigation: scaffold commit 1 proves pnpm install + cargo build + one passing test on all three OSes before any feature code; any bet that fails that gate is dropped to its fallback on the spot and this page is re-issued.

Verification

How these numbers were obtained, and how they stay true.

How each version was read

  • npm: npm view <pkg> version + dist-tags --json + time (publish dates) + peerDependencies for the RC set.
  • crates: crates.io/api/v1/crates/<crate> (max_stable_version, updated_at, feature flags).
  • tools/actions: gh api repos/<r>/releases/latest and tag/branch refs (tauri-action v1 alias and dtolnay beta branch confirmed).
  • Rust/Node: static.rust-lang.org channel TOMLs (beta = 1.99.0-beta.1, channel 2026-08-18), nodejs.org release schedule (v26 LTS 2026-10-28).
  • First pass by one worker (59 items), then an independent refuter re-ran every lookup: 59/59 confirmed, 0 weakened, 0 refuted. 74 further items (plugins, test libs, actions, feature flags, RC tags) looked up by script today: research/bom-extra.txt + the v2 RC pass.

How they stay pinned

  • rust-toolchain.toml (dated beta), .nvmrc, packageManager pin the toolchain; Cargo.lock and pnpm-lock.yaml freeze every transitive version and are committed. Pre-release pins are exact (no caret).
  • CI installs with --frozen-lockfile / --locked; cargo deny check gates advisories and licenses.
  • This page is re-issued (same link) if any pick changes during scaffolding — a silent substitution is the failure mode this doc exists to prevent.
